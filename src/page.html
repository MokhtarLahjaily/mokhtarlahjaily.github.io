Agentic automation of support ticketsAutomatisation agentique des tickets de support

Card-payment support agents answer the same informational questions ticket after ticket, and banking data can't leave the company. My final-year project: an agent that takes those tickets off their plate, running entirely on-premise.

Les agents du support monétique répondent aux mêmes questions informationnelles, ticket après ticket, et les données bancaires ne peuvent pas quitter l'entreprise. Mon projet de fin d'études : un agent qui les décharge de ces tickets, entièrement hébergé en interne.

How it worksComment ça marche

A chat widget in the iTop portal sends each request to a tool-calling agent. It reasons with a local LLM served by Ollama, and pulls facts through read-only tools: hybrid RAG over a curated knowledge base, a knowledge graph, a memory of past resolutions, and 29 iTop REST tools, also exposed through an MCP server.

Un widget de chat dans le portail iTop transmet chaque demande à un agent à appel d'outils. Il raisonne avec un LLM local servi par Ollama et va chercher les faits par des outils en lecture seule : un RAG hybride sur une base de connaissances curée, un graphe de connaissances, une mémoire des résolutions passées et 29 outils REST iTop, aussi exposés par un serveur MCP.

The agent only reads. Its single write path is creating an escalation ticket with the context filled in, so it can't close a case it shouldn't.

L'agent ne fait que lire. Son seul chemin d'écriture est la création d'un ticket d'escalade contextualisé : il ne peut pas clore un dossier à tort.

What I trainedCe que j'ai entraîné

  • A CamemBERT intent classifier, fine-tuned on 773 utterances I labelled by hand: macro-F1 0.87 against 0.56 for the zero-shot LLM, about 46× faster.
  • Un classifieur d'intentions CamemBERT, affiné sur 773 énoncés que j'ai annotés à la main : macro-F1 de 0,87 contre 0,56 pour le LLM en zero-shot, environ 46× plus rapide.
  • Llama 3.1 8B aligned with DPO (QLoRA) on preference pairs built for the domain, since no training data existed.
  • Llama 3.1 8B aligné par DPO (QLoRA) sur des paires de préférences construites pour le domaine, faute de données existantes.

How I measured itComment je l'ai mesuré

A frozen 115-case harness scores intent, content, faithfulness and latency with an LLM judge, and ablation studies over embedders, rerankers and generators justify each component.

Un harnais figé de 115 cas note l'intention, le contenu, la fidélité et la latence avec un juge LLM, et des études d'ablation sur les modèles d'embeddings, les rerankers et les générateurs justifient chaque composant.
